## 2. Что сделано сильно и трогать не надо

Это не дежурная похвала: по этим местам видно выстраданное, и переделывать их —  
чистая потеря времени.

- **Дисциплина доказательства.** `tools/prove-fix.py` (78 шагов) не даёт  
  «починить и забыть»: каждый шаг откатывает поведение, гоняет проверку и  
  возвращает файл. `check-library-live.cjs` берёт `app.js` **у демона**, а не с  
  диска — ловит устаревшую копию, вшитую в exe.
- **Безопасность по построению.** Мутации только POST; `originGuard` + проверка  
  `Sec-Fetch-Site` на всех методах; whitelist схем `http/https`; запуск плеера  
  массивом аргументов без оболочки; разметка строится через `html``` с
  экранированием по построению (132 вызова `esc()\` → 3 законных).
- **Честные отказы.** Недоступная папка называется словами рядом с полем, причина  
  отсутствия постеров — в верхней строке, занятый чужим порт отличается от «наш  
  ещё поднимается», готовность TorrServer проверяется по ответу `/echo`, а не по  
  открытому сокету.
- **Портативность как принцип.** Интерфейс в exe, кэш и постоянные данные  
  разведены по папкам, сторож перезапусков считает попытки, архив состояния не  
  увозит ключ TMDB и не затирает состояние, если архив испорчен.

## 3. Что реально не доделано


### P0 — портативность и секреты

**1. Абсолютные пути в конфиге ломают перенос.** README обещает: «`watch_folder`  
и `download_folder` заданы относительно exe-бинарника — папка работает с любого  
диска». В `torrclient.json` лежат абсолютные `Y:\TorrClientPortableXX\watch` и  
`…\downloads`: они пишутся в конфиг при первом запуске (`config.go:61-62` —  
`filepath.Join(exeDir(), …)`) и потом едут вместе с ним. Перенесли папку на диск  
с другой буквой — пути ведут в никуда. Спасает только то, что `folders.go`  
проверяет доступность настоящей записью при старте и предупреждает; но  
предупреждение не лечит.

> Что делать: empty = «рядом с программой» уже поддерживается  
> (`applyStoragePaths`, `absToExe`). Значит, надо (а) не подставлять absolutные  
> значения при первом запуске, а оставлять пустыми/относительными, (б) при  
> сохранении конфига переводить путь, лежащий внутри `exeDir()`, обратно в  
> относительный, (в) покрыть это тестом «сменили букву диска — пути живы».

**2. Пароль профиля TorrServer уезжает в архив.** `backupSecrets` знает только  
`tmdb_api_key` и `tmdb_access_token` (`backup.go:37`). `Profile.Pass`  
(`config.go:22`) ничем не защищён: архив состояния, отданный другому человеку  
или приложенный к сообщению о проблеме, отдаёт и пароль. Логика уже есть —  
добавить поле в список и тест по образцу `backupsecrets_test.go`.

**3. Ключ TMDB скомпрометирован.** Он лежит в `torrclient.json` открытым текстом  
и попадал в переписку и в чат. Отозвать на themoviedb.org и завести новый  
(Настройки → TMDB, без перезапуска). Это не задача кода — это задача  
пользователя, и она единственная в списке, которую нельзя закрыть правкой.


### P1 — качество и мёртвый вес

**4. Покрытие 45 % — с большими дырами.** По файлам (функции с ненулевым  
покрытием):

| Файл                         | Покрыто    |
| ---------------------------- | ---------- |
| `registry.go`                | **0 из 9** |
| `events.go`                  | 3 из 10    |
| `kinozal.go`                 | 3 из 7     |
| `player.go`                  | 17 из 36   |
| `proxy.go`                   | 6 из 10    |
| `profiles.go`, `userdata.go` | 2 из 4     |

Хуже всего то, что **SSE-лента (`events.go`) не покрыта вовсе** — а это именно то,  
чем интерфейс живёт. `registry.go` не покрыт и не может быть покрыт в этой  
песочнице (`reg.exe` заблокирован) — значит, разбор вывода `reg query` надо  
вынести в чистую функцию, как уже сделано для остальных парсеров, и тестировать  
её без реестра.

**5. Мёртвый код в `web/app.js`.** Пять функций определены и ни разу не вызваны:  
`forgetPosters`, `isSub`, `openModal`, `torrentStreamUrl`, `urlSafe`. Проверить и  
удалить — либо вернуть к делу (см. п. 16 про субтитры).

**6. Кинозал висит мёртвым провайдером.** Ни одно зеркало не отдаёт выдачу из  
этой сети; `kinozal.go` покрыт на 3/7. Либо убрать из `SEARCH_PROVIDERS`, либо  
честно показывать в интерфейсе «источник недоступен» вместо пустой выдачи.  
Третьего нет: провайдер, который молча не работает, хуже отсутствующего.

**7. README устарел.** Пишет про кэши `.gocache` внутри папки (он уведён на  
локальный диск), про `wails build` без упоминания `npm install`, и про  
относительные пути, которых в конфиге нет (п. 1).

**8. Мусор в проекте:** `_tmp_check.go.disabled` в корне,  
`app/build/bin/TorrClient-previous.exe` (11,7 МБ), `app/torrclient.exe`  
(9,7 МБ — назначение надо проверить: оболочка ищет демон по имени, поднимаясь  
вверх, и эта копия может подхватываться вместо корневой).


### P2 — продукт

**9. Нет трей-иконки.** Приложение существует только пока открыто окно. Для  
фоновой раздачи это странно: закрыл окно — непонятно, живо ли что-то.

**10. Нет проверки обновлений.** Версию TorrServer мы уже умеем читать — `/echo`  
отдаёт её строкой (это сделано в итерации 16). Значит, сверка «какая версия  
лежит рядом и есть ли новее» дешева: показывать версию в интерфейсе и  
предлагать обновление движка.

**11. Нет встроенного плеера.** Сейчас без внешнего VLC/MPC смотреть нечем; поток  
уже проксируется демоном, адрес для `<video>` есть. Это крупная работа с  
честным ограничением: MKV с HEVC и звуком DTS браузер не проиграет, и обещать  
обратное нельзя (`HESTIA-REVIEW.md`, §3).

**12. Нет диагностики одним файлом.** При разборе чужой установки первое, что  
нужно: версия сборки, пути папок и их доступность, найденные плееры, жив ли  
TorrServer, размер кэша. Всё это уже есть по отдельности — осталось собрать в  
кнопку «Диагностика» без секретов в выгрузке (§2.9 того же разбора).

**13. Нет версии формата состояния.** `viewed.json`/`userdata.json` пишутся без  
поля версии; пока старый файл читается — это везение, а не гарантия (§2.10).

**14. TEMP дочерних процессов уходит в систему.** TorrServer оставляет  
временные файлы в системном `%TEMP%` — на чужой машине это следы (§2.6).  
Направить TEMP/TMP в переносимую папку рядом с кэшем.

**15. Мелочи интерфейса:** нет «О программе» с версией сборки (версия  
подставляется ldflags, узнать её из UI негде); клавиатура — только Esc и Enter в  
поиске; тёмной темы нет; истории поиска и автодополнения нет; очистить кэш  
постеров из UI нельзя (есть только потолок 4000 записей в демоне).

**16. Субтитры не поддержаны.** `isSub()` умеет распознавать `.srt/.ass/.vtt`,  
но не вызывается ни разу: дорожки из раздачи не показываются и не подключаются.  
Либо поддержать (выбор дорожки в окне раздачи, отдача её плееру), либо удалить  
функцию, чтобы не вводила в заблуждение.


## 4. Что значит «довести до конца»

Проект такого рода не бывает «готов» вообще — но бывает готов к передаче другому  
человеку. Ниже — критерии, по которым это видно. Сейчас зелёные пункты 1, 2, 5  
(частично), остальные — нет.

1. **Гейты в один вызов.** `gofmt` → `vet` → `test` (демон и оболочка) →  
   `node --check` → `check-series.js` → `prove-fix.py` без единого `ПРОПУСК`. ✅
2. **Релиз одной командой.** `make-release.py` собирает папку, проверяет, что  
   ключа в ней нет и что вшитый `app.js` совпадает с исходником байт в байт. ✅
3. **ффХолодный старт на чистой машине.** Распаковал → `start_desktop.bat` → окно  
   открылось, поиск ищет, раздача идёт, плеер нашёлся. ❌ (проверялось только на  
   этой машине, где плеера нет вовсе.)
4. **Перенос.** Скопировал папку на другой диск/букву — всё работает без правок  
   конфига. ❌ (п. 1 раздела 3.)
5. **Секреты.** Ключ TMDB и пароли профилей не покидают машину: нет их ни в  
   архиве, ни в журнале, ни в диагностике. ❌ для пароля профиля (п. 2).
6. **Откат.** Любая правка откатывается одной командой. ❌ — git в проекте нет  
   вовсе, откат = «повтори прогон `prove-fix.py` до конца».
7. **Покрытие доменов.** Не процент вообще, а отсутствие дыр: SSE, прокси,  
   профили, userdata, разбор реестра — покрыты. ❌ (45 %, дыры в таблице выше.)
8. **Документация соответствует коду.** README, CHANGELOG и комментарии не врут  
   про то, что изменилось. ❌ (п. 7.)
9. **Понятно, что дальше.** Есть список, из которого видно, что делать следующим  
   вечером. ❌ до этого файла.


## 5. План по этапам

Порядок не по «важности вообще», а по цене ошибки: сначала то, без чего нельзя  
безопасно продолжать.

  оставляет файл в сломанном виде.
- Один скрипт `check-all` (bat + sh), который гонит все гейты подряд. Сейчас их  
  семь, и они живут в памяти, а не в репозитории.

**Этап 1. Портативность и секреты.** Пункты 1, 2, 3. Каждый — с тестом и шагом в  
`prove-fix.py`. Ключ TMDB отозвать.

**Этап 2. Чистка и тесты.** Удалить мёртвый код (п. 5) и мусор (п. 8); закрыть  
дыры покрытия — сначала `events.go` (SSE) и `proxy.go`, потом `profiles.go` и

**Этап 3. Продукт-мелочи (каждая — на вечер).** Трей-иконка (п. 9); версия

**Этап 5. Релиз-цикл.** Версия в одном месте (сейчас она и в `-ldflags`, и в

инструкция «как обновиться, не потеряв состояние» (архив состояния уже есть —  
описать им пользоваться).

## 7. Чего делать не надо

- **Не переходить на Svelte/TypeScript/npm.** Весь интерфейс — один `app.js`,  
  вшитый в exe и сверяемый байт в байт; сборка через Node это ломает.
- **Не менять JSON на BoltDB.** Данных — десятки записей; JSON читается глазами,  
  переносится архивом и объясняется пользователю.
- **Не делать Jackett основным источником.** Прямой разбор rutor работает и  
  покрыт проверками; Jackett — лишний процесс на 60+ МБ, который надо ставить.
- **Не разбивать `app.js` на ES-модули**, не переведя одновременно  
  `tools/check-*.js` на `vm.SourceTextModule`. Иначе проверки тихо начнут  
  проверять не то.
- **Не городить «витрину тем» и украшения** — это не приближает ни к одному  
  критерию из раздела 4.

## 8. Первые пять шагов

1. `git init` + первый коммит + `.gitignore`. Всё остальное делается уже с  
   возможностью отката.
2. Отозвать ключ TMDB и завести новый.
3. Относительные пути в конфиге (п. 1) + тест на перенос.
4. `profiles[].pass` в `backupSecrets` (п. 2) + тест.
5. Убрать мёртвый код и мусор, поправить README (пп. 5, 7, 8).

Пункты 3–5 — по одному вечеру каждый, и каждый закрывается шагом в  
`tools/prove-fix.py`.
