# Разбор соседнего проекта «Гестия»: что взять (27.09.2026)

Смотрел `Y:\Гестия\12` — там второй, независимо написанный клиент вокруг того же
TorrServer: Wails v2 + Svelte/TypeScript, хранение в BoltDB, поиск через
Jackett/Torznab, встроенный HTML5-плеер, метаданные OMDb/Кинопоиск/TMDB.

Отдельная находка: рядом лежит **полный исходник TorrServer**
(`Y:\Гестия\12\.tools\TorrServer`, версия `MatriX.144`) и исходник Jackett. Это
позволяет сверять контракт по коду, а не по догадке.

Ниже: сначала то, что у нас **уже сделано так же** (менять нечего), потом идеи,
которые стоит взять, потом то, что брать не нужно.

## 1. Что у нас уже так же (проверено по коду, действий не требует)

| Правило «Гестии» | У нас |
|---|---|
| Секрет не возвращается в интерфейс — только признак «задан» | `/api/meta` отдаёт только `configured`, ключ в браузер не уходит (`tmdb.go:297`) |
| Имена раздач — недоверенный ввод; запуск только массивом аргументов, без оболочки | `argSafe` срезает кавычки и переводы строк (`proxy.go:131`), `exec.Command(path, args...)`, есть тесты (`guards_test.go:46`) |
| Поиск плееров без рекурсивного обхода личных каталогов | `filepath.Walk`/`Glob` в проекте не используются вовсе |
| Ограничение размера ответа | `io.LimitReader(resp.Body, 1<<22)` — 4 МБ на страницу трекера (`rutor.go:494`) |
| Снятие дублей по хешу при слиянии источников | `mergeResults` в `web/app.js:1657`, `dedupeItems` в `rutor.go:140` |
| `index` у TorrServer считается с единицы | подтверждено по исходнику: `Id: i + 1, // in web id 0 is undefined` (`server/torr/torrent.go:377`); наш интерфейс передаёт именно `f.id` — согласовано |
| Защита от второго окна | `acquireSingleInstance` (`app/main.go:35`) — у «Гестии» этого нет |

Отдельно: у «Гестии» был тот же урок про `\b` и кириллицу — она решает его
`(?:^|[^\pL\pN])` вместо `\b` (`internal/media/media.go:22`). Мы к тому же пришли
сами, шаг отката в `tools/prove-fix.py` это стережёт.

## 2. Что стоит взять

### 2.1. Отметку просмотра не сбрасывать на диск только при выходе плеера

**У «Гестии»:** «saves are exposed for pause, every 5 seconds of playback, and on
close» (`TASKS.md`, W3). В store запись идёт сразу при сохранении.

**У нас:** во время просмотра отметка живёт **только в памяти**, файл пишется один
раз — при закрытии плеера (`player.go:665–671`, там это даже объяснено: «Позиция
меняется каждые пять секунд — писать ради неё viewed.json так же часто незачем,
хватит одной записи при выходе»).

**Чем плохо:** аварийное завершение (перезагрузка, отключение диска, снятие
процесса) теряет позицию **целого сеанса**. Для портативного диска, который
перезагружается, это не редкий случай.

**Что сделать:** сбрасывать отметку на диск периодически во время просмотра.
Каждые 5 секунд не нужно — наш файл переписывается целиком, а не пишется записью в
базу; разумный шаг — 30–60 секунд, плюс как сейчас при выходе. Потеря тогда
ограничена шагом, а не сеансом.

### 2.2. Архив с настройками увозит ключ TMDB

**У «Гестии»:** «Exported diagnostics must **exclude** credentials and API keys —
write a test that asserts this» (`TASKS.md`, W5).

**У нас:** `backupFiles = {"torrclient.json", "userdata.json", "viewed.json"}`
(`backup.go:28`), а в `torrclient.json` лежит `tmdb_api_key` открытым текстом.
Значит, любой архив, отданный другому человеку или приложенный к сообщению о
проблеме, отдаёт и ключ.

**Что сделать:** при сборке архива вырезать `tmdb_api_key` и `tmdb_access_token`
из копии `torrclient.json` (сам файл на диске не трогать), а при возврате архива
оставлять ключ, который уже есть у пользователя. Добавить проверку, что ключа в
архиве нет, — по образцу того, как это уже проверяет `tools/make-release.py`.

### 2.3. Сторож перезапускает процессы без счёта

**У «Гестии»:** не больше трёх перезапусков с паузой в секунду, состояние и текст
ошибки уходят в интерфейс (`internal/process/manager.go:126, 154`), и отдельно
разведены «поднять после чистого выхода» (`KeepAlive`) и «поднять после падения»
(`Restart`).

**У нас:** `healthLoop` каждые 5 секунд зовёт `startTorrServer` и `startDaemon`
без ограничения числа попыток (`app/app.go:78–90`). Демон, падающий при старте,
поднимается заново **каждые 5 секунд бесконечно и молча** — пользователь видит
только пустое окно.

**Что сделать:** считать попытки подряд, останавливаться после нескольких и
показывать причину (панель «Сервер» для этого уже есть). Счётчик сбрасывать после
успешного запуска, который прожил заметное время.

### 2.4. Возврат архива не проверяет то, что кладёт

**У «Гестии»:** «a bad import must leave the existing database untouched»
(`TASKS.md`, W3).

**У нас:** архив читается целиком до первой записи — это хорошо
(`backup.go:105–129`), но содержимое не разбирается. `torrclient.json` из архива
пишется на место рабочего **без проверки** (`backup.go:132–141`), и только потом
`reloadConfigPaths()` пытается его прочитать. Испорченный файл в архиве затирает
рабочие настройки.

**Что сделать:** разобрать каждый файл архива до записи и при первой же ошибке
отказать целиком, ничего не записав.

### 2.5. Готовность TorrServer проверять по `/echo`, а не по открытому порту

**У «Гестии»:** проба готовности с проверкой тела ответа и разбором случая «процесс
умер, не дождавшись» (`indexer.go:120–139`); отдельно записан пойманный дефект:
после перезапуска `/echo` уже отвечал, а «подключено» оставалось ложным.

**У нас:** оболочка ждёт **открытия порта** (`portOpen`, `app/app.go:211`). Порт
может открыться раньше, чем сервер начнёт обслуживать: в комментарии к
`tsStartGrace` это уже отмечено («проверка DNS и открытие базы»).

**Что сделать:** ждать ответа `/echo` (отдаёт строку версии, авторизации не
требует — `server/web/server.go:85`, `route.GET("/echo", echo)`), а не открытия
сокета. Заодно появится возможность показать версию TorrServer в интерфейсе.

### 2.6. Дочерним процессам задать свой TEMP

**У «Гестии»:** `cmd.Env = append(os.Environ(), "TEMP="+temp, "TMP="+temp,
"TMPDIR="+temp)` в отдельный переносимый каталог (`manager.go:70`), и сам каталог
описан в раскладке рядом с данными и кэшем (`internal/app/root.go:13–28`).

**У нас:** дочерним процессам задаётся только рабочий каталог (`app/app.go:229,
308`) — временные файлы TorrServer уходят в системный TEMP и остаются на чужой
машине.

**Что сделать:** направить TEMP/TMP в переносимую папку рядом с программой. Логично
рядом с кэшем: она такая же одноразовая.

### 2.7. Прекращать ожидание, если процесс уже умер

**У «Гестии»:** цикл готовности прерывается сразу, как только процесс перестал
работать (`indexer.go:128`).

**У нас:** `startDaemon` ждёт порт 200 раз по 75 мс (`app/app.go:334`), не глядя на
то, жив ли запущенный процесс, — то есть 15 секунд впустую и без объяснения.

**Что сделать:** выходить из ожидания, когда процесс завершился, и говорить об этом.

### 2.8. Проверять занятость порта до запуска

**У «Гестии»:** порт проверяется до запуска, и при занятости — понятный отказ
(«Порт занят или недоступен; существующий сервис не будет остановлен»,
`indexer.go:96–100`). Правило «не останавливать то, что поднял не ты» записано
прямо.

**У нас:** занятый порт не отличается от «наш ещё не поднялся»; при этом
`stop_all.bat` снимает процессы **по имени образа**, то есть и чужие копии тоже.

**Что сделать:** как минимум отличать «порт занят чужим процессом» от «наш
поднимается» и говорить об этом. `stop_all.bat` — осознанная кнопка «остановить
всё», но её поведение стоит описать в README.

### 2.9. Диагностика одним файлом, без секретов

**У «Гестии»:** «root, version, connectivity, process states, cache size, detected
players, collected errors», с проверкой, что секретов в выгрузке нет (`TASKS.md`,
W5).

**У нас:** есть журнал и архив состояния, но нет сводки «что за сборка, какие папки,
какие плееры найдены, жив ли TorrServer, размер кэша». При разборе проблемы это
первое, что нужно.

**Что сделать:** добавить кнопку «Диагностика» — текстовый файл с этой сводкой.
Полезно ровно настолько, насколько часто приходится разбирать чужую установку.

### 2.10. Версия формата состояния и копия перед сменой

**У «Гестии»:** `schemaVersion` в базе, резервная копия перед любой сменой схемы
(`TASKS.md`, W3).

**У нас:** в JSON-файлах версии нет. Пока формат менялся так, что старый файл
читался, но это везение, а не гарантия.

**Что сделать:** поле версии в `viewed.json`/`userdata.json` и копия рядом перед
первым изменением формата. Ценность отложенная — браться не первым делом.

## 3. Крупная идея: смотреть внутри программы

**У «Гестии»:** встроенный HTML5-плеер (`<video>`) со своей позицией и переходом к
следующей серии, а внешний плеер — запасной путь. При этом честно записано:
«HTML5 cannot guarantee MKV/HEVC/DTS support: detect playback failure and offer
external player, no pretend transcoding» (`IMPLEMENTATION_PROMPT.md`).

**У нас:** без внешнего плеера смотреть нечем — `player_path` пуст, и на этой машине
плеера нет вовсе. Поток уже проксируется нашим демоном (`/ts/stream/...`), то есть
адрес для `<video>` есть.

**Что это даёт:** программу можно будет использовать сразу после распаковки, не
устанавливая ничего. **Чего не даёт:** MKV с HEVC и звуком DTS браузер не проиграет —
там нужен внешний плеер, и обещать обратное нельзя. Формат, который отдаёт
TorrServer, тоже не всегда подходит браузеру.

**Вывод:** идея сильная, но это отдельная работа с честным ограничением по
кодекам, а не мелкая правка.

## 4. Что брать не нужно

- **BoltDB вместо JSON.** Объём данных у нас — десятки записей; файл проще читать
  глазами, переносить архивом и объяснять пользователю. Лишняя зависимость.
- **Svelte + TypeScript + npm.** Сборка через Node противоречит тому, что сейчас
  весь интерфейс — один `app.js`, вшитый в exe и проверяемый байт в байт.
- **Jackett/Torznab как основной источник.** Наш прямой разбор rutor и Кинозала
  работает и покрыт проверками; Jackett — это ещё один процесс на 60+ МБ, который
  придётся ставить и настраивать. Torznab у нас уже есть как дополнительный
  источник.
- **Своя витрина тем и «очаг».** Красиво, но к делу не относится.

## 5. Итог

По-настоящему ценного немного, и оно не про архитектуру, а про надёжность:

1. периодический сброс отметки просмотра (2.1) — иначе аварийное закрытие съедает
   позицию сеанса;
2. ключ TMDB в архиве (2.2) — утечка секрета при передаче архива;
3. счёт попыток у сторожа (2.3) — иначе молчаливый вечный перезапуск;
4. проверка архива до записи (2.4) — иначе испорченный архив затирает настройки.

Остальное (2.5–2.10) — по мере надобности. Встроенный плеер (3) — отдельная
крупная работа с честным ограничением по кодекам.
