# TorrClient — портативная сборка

Переносимая версия программы (демон + веб-интерфейс + десктоп-оболочка Wails + движок TorrServer).

## Запуск

| Способ | Действие |
| ------ | -------- |
| Десктоп | двойной клик по `app\build\bin\TorrClient.exe` или `start_desktop.bat` (оболочка сама запустит TorrServer на `127.0.0.1:8090` и демон на `127.0.0.1:8099`) |
| Браузер | `start_web.bat` — запускает `torrclient.exe`, который сам откроет `http://127.0.0.1:8099` |

Остановка всех процессов: `stop_all.bat`.

## Структура

```
TorrClientPortable/
  torrclient.exe                 <- демон (веб-интерфейс вшит в exe, Go embed)
  torrclient.json                <- конфиг: профили TorrServer, плееры, папки (в т.ч. кэша и постоянных данных)
  userdata.json                  <- избранное и закладки (папка постоянных данных)
  viewed.json                    <- отметки просмотра (папка постоянных данных)
  tmdb-cache.json                <- кэш постеров и оценок (папка кэша; можно удалять)
  torrclient.log                 <- журнал работы (папка кэша; можно удалять)
  TorrServer-windows-amd64.exe   <- движок торрентов (TorrServer)
  main.go, go.mod                <- исходники демона
  web/                           <- исходники интерфейса (app.js, style.css, index.html)
  app/                           <- исходники десктоп-оболочки (Wails) + сборка TorrClient.exe
  downloads/  watch/             <- папки загрузок и наблюдения (создаются автоматически)
  README.md
```

## Портативность

- `watch_folder` и `download_folder` в `torrclient.json` заданы относительно exe-бинарника —
  папка работает с любого диска, не зависит от текущего каталога и буквы диска.
- `cache_folder` и `data_folder` разводят одноразовое и постоянное: кэш
  (`tmdb-cache.json`, `torrclient.log`) можно положить на диск, который очищается при
  перезагрузке, — потерять его не страшно. Отметки просмотра и избранное лежат в
  `data_folder` и должны быть на постоянном диске. По умолчанию обе папки — каталог программы,
  так что обновление ничего не переносит. Меняются в «Настройки → Где хранятся данные».
- Web-интерфейс встроен в `torrclient.exe` (директива `//go:embed web`), поэтому папка `web/` не обязательна для запуска — нужна только для правки кода.
- Торрент-движок (TorrServer) ищется оболочкой рядом с собой — класть `TorrServer-windows-amd64.exe` и `torrclient.exe` в корень папки обязательно.
- Профиль TorrServer (`http://127.0.0.1:8090`) заводится оболочкой автоматически при запуске.

## На новом компьютере

1. Скопируйте папку целиком на любой диск (не обязательно D).
2. `TorrServer-windows-amd64.exe` должен быть доступен на запуск (иногда Windows блокирует скачанные exe — при необходимости разрешите в свойствах файла).
3. Плееры: пути VLC/PotPlayer/MPC задаются в «Настройки → Плееры» (кнопка «Найти плееры»). Путь из старого конфига (`E:\...\VLC\vlc.exe`) на новом ПК скорее всего не подойдёт — нажмите пересканирование.
4. Рекомендуется `start_desktop.bat` — оболочка сама поднимет TorrServer и демон.

## Индексаторы Torznab

Поиск по Torznab идёт из демона напрямую в индексатор, мимо TorrServer. Обычно это Jackett или Prowlarr:

1. В индексаторе найдите Torznab-адрес (в Jackett — «Copy Torznab URL» у трекера, в Prowlarr — `/api/v1/indexers/<имя>/results/torznab/api`). Обычно он выглядит так: `http://127.0.0.1:9117/results/torznab/api?apikey=...`
2. «Настройки → Индексаторы Torznab»: вставьте строку целиком, ключ выделится сам из адреса. Нажмите **Проверить** — демон спросит capabilities и одну раздачу и покажет, что именно не так, если что-то не так.
3. **Добавить**. После этого Torznab появляется в списке источников на странице «Поиск» и догружается кнопкой «ещё».

Ключи хранятся в `torrclient.json` и никогда не отдаются в браузер целиком: в настройках видно только `ключ a…xy`. Правка адреса не обнуляет прежний ключ. Сам `torrclient.json` в сборку релиза не входит.

Проверка ничего не сохраняет — это осознанно: кнопка «проверить» не должна быть кнопкой «применить».

## Автообновление

Интерфейс раз за сеанс спрашивает демон о новой версии (демон ходит в GitHub Releases не чаще раза в 6 часов). Если вышла новая — рядом со значком версии появляется кнопка «⬆ X.Y.Z»: окно с описанием и «Обновить сейчас». Архив для своей системы скачивается, сверяется с `SHA256SUMS.txt`, файлы программы заменяются (занятые переименовываются в `*.old` и удаляются при следующем запуске), демон перезапускается. Настройки и данные не трогаются. Проверку можно отключить: Настройки → О программе.

## Доступ с телефона

Настройки → «Доступ с телефона» → «Разрешить вход». Программа откроет второй порт (по умолчанию 8100) на всех адресах компьютера и покажет QR-код с адресом и PIN. Телефон в той же Wi-Fi-сети открывает QR камерой и получает сессию на 30 дней. Без PIN'а (или cookie сессии) ничего не открывается; 8 неверных попыток за 10 минут блокируют адрес. С телефона недоступны резервная копия, реестр, автозапуск и установка программ. «Новый PIN» отключает все вошедшие телефоны. Основной порт 8099 по-прежнему слушает только 127.0.0.1.

## Лучшая раздача

Кнопка «★ Лучшая» в поиске (и клик по постеру в подборках) опрашивает rutor, Кинозал и Torznab параллельно, склеивает одинаковые раздачи (по хэшу или названию и размеру) и выбирает лучшую по качеству и числу сидов. Раздачи почти без сидов опускаются вниз.

## Автонастройка буфера

Сервер → Настройки → «Автонастройка буфера»: замер скорости канала (≈25 МБ с speed.cloudflare.com) и подбор кэша, предзагрузки и числа соединений TorrServer под него.

## Поиск

- **Источники:** rutor, Кинозал.ТВ, свои Torznab-индексаторы (переключатель «Источник», есть режим «Все источники»).
- **Torznab идёт потоком:** все индексаторы опрашиваются одновременно (`/api/torznab/stream`), выдача рисуется по мере ответов, медленный индексатор не задерживает остальных. Не ответивший за 12 секунд показывается строкой с причиной под списком.
- **Популярное:** кнопка «Популярное» рядом с «ТОП-24» показывает раздачи выбранной категории rutor за всё время по числу сидов (`/api/popular`), «Показать ещё» подгружает следующие страницы.

## Где править интерфейс

Код интерфейса лежит частями в `web/src/` (по разделам: `00-core.js` — общее и запуск, `50-search.js` — поиск, `80-settings.js` — настройки и т. д.). `web/app.js` — их склейка, которую отдаёт демон: после правки запустите `node tools/build-web.cjs`. Тест и CI сверяют, что `app.js` собран из актуальных частей.

## Автопроверка и релизы

- **CI** (`.github/workflows/ci.yml`): на каждый пуш и PR GitHub собирает проект и гоняет `go vet`, `go test`, проверку `app.js` и образцы оценки качества — под Windows и Linux. Статус виден в PR.
- **Релиз** (`.github/workflows/release.yml`): когда в `main` меняется `VERSION`, публикуется релиз `vX.Y.Z` с архивами `TorrClient-X.Y.Z-windows-amd64.zip` и `…-linux-amd64.tar.gz` (демон и веб-интерфейс). В Windows-архив входит и окно `TorrClientDesktop.exe` (Wails; своё имя, потому что Windows не отличает `TorrClient.exe` от демона `torrclient.exe`, собирается на windows-latest); рядом лежит `SHA256SUMS.txt`. CI собирает окно в каждом PR.

## Кинозал: зеркала

Первыми проверяются официальные домены — `kinozal.tv`, `kinozal.me`, `kinozal.guru`. Неофициальные зеркала — запасной путь; `kinozal.jumpingcrab.com` и `kinozaltv.appspot.com`, которые форум Кинозала прямо называет поддельными, в список не входят. Следующий поиск начинается с зеркала, ответившего последним. В Настройки → «Кинозал: зеркала» можно добавить свои адреса, запретить неофициальные и проверить все зеркала разом. Программа на Кинозал не входит и пароль туда не передаёт.

## Интерфейс: тема и горячие клавиши

- **Темы:** тёмная, светлая, как в системе, чёрная (OLED), северная, Дракула, лес, сепия. Выбор в Настройки → Оформление; кнопка 🌓 в шапке или клавиша `T` перебирают их по кругу. Темы — только наборы цветов, на скорость не влияют.
- **Клавиши:** `/` или `Ctrl+K` — поиск, `Alt+1…Alt+0` — разделы по порядку, `Esc` — закрыть окно, `?` — список клавиш.
- **История поиска:** последние запросы подсказываются при вводе, запись удаляется крестиком.
- **Версия:** значок в шапке (номер из файла `VERSION`), по нажатию — «Что нового».

## Linux, macOS и режим без окна

Демон (`torrclient`) собирается под Linux и macOS: `GOOS=linux go build -o torrclient .`. Системные части лежат отдельно (`platform_windows.go`, `platform_unix.go`), остальной код общий.

- **Без окна:** `torrclient --open=false` — только демон и веб-интерфейс на `http://127.0.0.1:8099`. С `--host 0.0.0.0` до него можно достучаться с телефона в той же сети: API при этом не защищён паролем, включайте только в доверенной сети.
- **Открытие ссылок:** `xdg-open` (Linux) и `open` (macOS), на Windows — как раньше.
- **magnet: и .torrent:** на Linux регистрируются файлами `.desktop` в `~/.local/share/applications` (кнопка в настройках); на Windows — записью в реестре; на macOS пока не поддерживается.
- **Автозапуск демона при входе в систему:** галочка в настройках (реестр на Windows, `~/.config/autostart` на Linux).
- **Плееры:** ищутся по файлам (`Program Files`, `/usr/bin`, `/snap/bin`, `/Applications` и т. п.) и в `PATH`; реестр Windows остаётся запасным путём.
- Трей и окно (Wails) пока только для Windows.

## Пересборка

Нужен Go 1.25 или новее (модули подтянутся из сети). Скрипт `build_daemon.bat` держит рядом с проектом только то, что должно ехать вместе с ним (`.go`, `.gomods`), а кэш компиляции кладёт на локальный диск: `%LOCALAPPDATA%\TorrClient\gocache` (переменная `TC_GOCACHE` это переопределяет). Кэш можно удалять в любой момент.

```
build_daemon.bat
# или вручную:
go build -ldflags "-s -w" -o torrclient.exe .
```

Десктоп-оболочка `app/`: нужны Wails CLI, Go с gcc/CGO и Node.js. Сначала `npm install` в `app/frontend`, затем `wails build`. Иконка задана в `app\wails.json`. В `app/main.go` есть защита от повторного запуска (появляется после пересборки).

Готовые `.exe` в репозиторий не входят (см. `.gitignore`): их собирают локально, а готовая портативная папка лежит в релизе (`tools/make-release.py`).

## Проверка

```
go build ./... && go vet ./... && go test ./...
python tools/check-all.py     # все проверки одной командой (check_all.bat на Windows)
```

Часть тестов (`players_test.go`) рассчитана на Windows и на другой ОС может падать.

## Что сознательно не копировали (генерируется/восстанавливается)

- `.go`, `.gomods` — окружение сборки Go (создаётся при `build_daemon.bat`),
- кэш компиляции Go — на локальном диске, см. выше,
- `app\build\bin\.webview` — профиль WebView2 (пересоздаётся при запуске),
- `app\frontend\node_modules` — npm-зависимости (ставятся `npm install`),
- `torrclient.exe~` — резервная копия предыдущего бинарника.

## Важно

- Избранное/закладки хранятся в `userdata.json`, отметки просмотра — в `viewed.json`; обе — в
  папке постоянных данных (`data_folder`, по умолчанию рядом с демоном). При смене папки файлы
  переносятся на новое место; то, что уже лежит в новой папке, не затирается.
- `torrclient.json` всегда остаётся рядом с демоном: в нём записаны обе папки, и другого места,
  откуда их можно было бы прочитать, нет.
- История просмотра (позиции файлов) живёт в самом TorrServer и хранится рядом с ним — для переноса вместе переносится и `TorrServer-windows-amd64.exe` с соседними данными программы.
